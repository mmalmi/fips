Router software for free or paid mesh networks

Freedom forwards encrypted data between devices running FIPS. Several routers can pass the data along, so the sender and receiver do not need a direct connection.

You can offer forwarding for free, or charge according to the amount of traffic. On a paid route, each router automatically pays the next router.

For internet access, use an exit. Nostr VPN provides internet exits through a trusted device or a paid provider. See how it fits with Freedom.

Current status: developer software tested on OpenWrt routers and Android phones. It requires compatible clients and manual setup. It is not yet a ready-to-use paid Wi-Fi internet hotspot.

OpenWrt setup instructions

What can I do with it?

  • Connect devices through several routers. For example, a device outside your direct Wi-Fi range can be reached through intermediate routers, provided there is a working chain of links.
  • Forward traffic for free. Set the forwarding price to zero. If the whole route is free, it needs no payment channels.
  • Charge for forwarding. Set a price for carrying other devices’ traffic. Test automatic payments to each router along the route using test funds.
  • Combine different kinds of connections. A route can include Wi-Fi, Ethernet and links over the existing internet.
  • Manage a router in OpenWrt. The optional Services → Freedom page shows peers, traffic and payment credit, and lets you start or stop the service.

Freedom transports data. It does not include a chat or file-sharing app; the devices need compatible FIPS software to send and receive it.

How does data get from one device to another?

Here is one possible route. Both phones run compatible FIPS software. The routers pass the encrypted data onward without reading its contents.

A mesh can have more links and alternative paths. FIPS discovers peers and routes data between them. Nearby Wi-Fi peers must still have compatible radio settings; installing Freedom alone does not connect arbitrary routers.

How does paid forwarding work?

The sender agrees to a route price and spending limit. Each router quotes its own fee plus the cost of forwarding through the next router.

Example price for a two-router route

Suppose router A charges 1 sat per MiB and router B charges 2 sats per MiB. A sat is a small unit of bitcoin; a MiB is 1,048,576 bytes.

Sender → router A → router B → destination
PaymentPer MiB of billable traffic
Sender pays A3 sats
A pays B2 sats
A retains its forwarding fee1 sat

Illustrative prices, not a live offer. These forwarding fees exclude funding costs and are not a profit estimate.

Payments accumulate across many packets using reusable payment channels between neighbors. Each router needs funds for its onward payments. You do not manually pay every router for every packet.

  • Payment system: Cashu, using Spilman payment channels. The Cashu mint is the service that issues and redeems the payment tokens; participants must trust it.
  • Limits: you set the maximum route price, lifetime spending and funds committed to channels.
  • Return traffic: replies need their own payment authorization, unless a free route or explicit return allowance applies.
  • Delivery: paying for forwarding does not prove that the destination received the data. An application may need to retry.

Public real-money operation has not been validated. The setup guide uses test funds.

How do I get internet access?

An internet exit connects your traffic to ordinary websites and other internet services. Freedom carries traffic between mesh nodes; an exit provides the connection beyond the mesh.

Nostr VPN provides client apps and internet exits. You can use a trusted device as your exit or buy bandwidth from an independent provider. You can also run an exit and set a price for its traffic. Paid exits are experimental.

The setup guide here configures Freedom relays. It does not yet configure or verify Nostr VPN over a paid Freedom route; that connection needs separate integration and testing.

Joining a Freedom router’s Wi-Fi does not automatically provide internet access or make a phone a paying client. Freedom does not include a hotspot sign-in or payment page.

What do I need to try it?

  • Compatible OpenWrt hardware. The package targets OpenWrt 25.12 or newer. Testing used ARM64 Cudy TR3000 v1 routers. Other models need their own compatibility and resource checks.
  • A link between devices. Start with a dedicated Wi-Fi mesh interface or Ethernet interface, while keeping your normal management network available.
  • Matching software builds and a compatible client. The Android FIPS Bench app has been built and tested on phones. It is a developer test tool, available as source, rather than an everyday VPN app.
  • Build and configuration work. There is no public signed one-click Freedom release or standard package-feed install yet. The current relay requires matched development dependencies.

Start with two nodes to check connectivity, then use at least three to test forwarding through an intermediate node. Add payments after the free route works.

What has been tested?

Controlled tests on Linux, three OpenWrt routers and Android phones running the test client cover paid forwarding, spending limits, route changes and recovery from selected failures.

That does not establish public real-money readiness, compatibility across different software versions, support for every OpenWrt router, or uninterrupted service while routers move around.

What is the difference between Freedom and FIPS?

FIPS is the underlying encrypted routing system. It gives devices cryptographic identities and routes traffic across different links.

Freedom is the forwarding service described on this site, including optional payments and the OpenWrt controls. It is implemented in the Iris FIPS repository as fips-relay. FIPS can also be used without paid forwarding.
