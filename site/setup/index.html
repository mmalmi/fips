A development setup, with real hardware evidence.

The relay and web UI work on the tested ARM64 OpenWrt routers. There is currently no public, signed, one-click Freedom release or standard package-feed install. Build the packages with the matched development dependencies, or use packages from a builder whose source and checksums you have verified.

A small, separate test network.

  • Two compatible routers for the first link; a third node or endpoint to test actual relaying. The physical bench used Cudy TR3000 v1 on ARM64.
  • OpenWrt 25.12 or newer with LuCI and SSH access. Verify support for your exact hardware revision before installing firmware. Older opkg/IPK systems need separate packaging work for this relay.
  • Persistent storage and enough free RAM. Accounts must survive reboot. Size storage for the executable, wallet database, journals and working space; the example’s 20 MiB wallet limit is not a whole-device sizing recommendation.
  • A separate management connection. Keep your usual LAN or management Wi-Fi available while changing the mesh interface.
  • Matching relay builds on participating nodes, plus synchronized clocks. Mixed-version payment compatibility is not established.

FIPS uses ordinary Linux interfaces. Two radios are convenient: one can serve clients and the other can connect mesh peers. A dedicated Ethernet interface is also a good first test.

Follow the source-bundle and OpenWrt packaging instructions for the exact dependency graph and your target CPU.

The UI source archive contains the LuCI files, its package builder and license; it does not include the relay or its dependencies. Extract it in a build directory. With an APKv3 tool that includes mkpkg, run the following as root in an isolated build environment. Replace the tool path and SOURCE_REVISION with the revision in the source manifest:

BUILD HOST · UI PACKAGE ONLY
sh crates/fips-relay/openwrt/build-luci-apk.sh /path/to/apk 0.1.0-r5 SOURCE_REVISION /output/luci-app-freedom.apk

Copy the two verified packages to the router’s /tmp directory. In this example, they have been named fips-relay.apk and luci-app-freedom.apk. Run over SSH:

ON THE ROUTER
apk add --allow-untrusted /tmp/fips-relay.apk /tmp/luci-app-freedom.apk

--allow-untrusted permits locally built unsigned packages. Use it only for artifacts you have verified. Required OpenWrt dependencies must already be installed or available from your configured feeds.

Reload LuCI after installation. Services → Freedom should appear. Installation leaves radio settings and existing accounts alone; it does not initialize or start the relay.

Give FIPS its own interface.

In Network → Wireless, prepare a dedicated mesh radio interface, conventionally named mesh0. Use a driver and installed Wi-Fi packages that support 802.11s mesh mode. Peers must use the same mesh ID, compatible security settings and the same channel to find one another.

  1. Keep mesh0 out of your LAN bridge. Preserve a separate management path.
  2. Disable 802.11s mesh forwarding on that interface. FIPS needs to forward each hop itself so lower-layer routing cannot bypass payment accounting.
  3. Use stable interface MAC addresses, then verify the interface and peer association after reboot.
  4. Use a lawful local radio country/channel configuration. A single shared channel is a small-bench starting point, not a global channel plan.
One mesh interface is not a public hotspot.

An optional customer-facing Wi-Fi network needs its own interface, DHCP and firewall rules. Expose only the intended FIPS entry and mint access before purchase; keep router administration isolated. The Freedom page does not create this network for you.

Native FIPS uses Ethernet frames on the prepared interface. The same mesh can also contain configured UDP, TCP or WebSocket links. Wi-Fi radio configuration remains OpenWrt’s job.

Free first. Deliberate limits.

Open Services → Freedom on each fresh router. The UI uses the installed example configuration when no active configuration exists.

  1. Select Free service and set Maximum route price to 0. This permits free onward routes only.
  2. Choose an existing Mesh interface, such as mesh0.
  3. Choose a trusted Cashu mint and bounded lifetime spending and locked-funds limits. Account initialization stores these settings even for a free-only test; a zero-priced path does not open payment channels.
  4. Click Save settings, then Create account once. Keep the entire new account state on persistent storage.
  5. Click Start. Enable startup at boot separately after the link works.

The UI enables authenticated adjacent-peer discovery on its configured native interface. Another compatible FIPS router on that link can become a peer without a hand-written identity roster. Authentication verifies its key; it does not make the neighbor trusted or grant unlimited spending.

Existing accounts keep their original terms.

Financial settings are read-only after any account state exists, including partial initialization. Stop/start preserves wallets and payment channels. Do not delete state or edit saved limits to change an account’s price. Plan a separate new account or follow the documented recovery procedure.

For CLI-managed setups, the UCI service normally points to /etc/fips-relay/config.json. The private control socket provides the same underlying service status:

STATUS CHECK · DEFAULT CONFIGURATION PATH
printf '%s\n' '{"type":"status"}' | fips-relay ctl /etc/fips-relay/config.json

Seeing a peer is the start.

  • Freedom says Running, meaning the actual relay responds. A running service wrapper alone is not enough.
  • Both routers show the expected connected peer. Check the native interface and clock if the service remains unavailable.
  • Use a compatible FIPS endpoint or the Android bench client to send a small flow and check reception at the destination.
  • For forwarding, arrange sender → relay → destination and confirm the intended links carry traffic. A direct alternate link can bypass the relay you meant to test.
  • Stop and restart the service; verify the same identity and account remain available.

The peer traffic counters include link traffic and are not an invoice. Accepted payments are signed credit, not settled wallet income or profit. Free-mode tests should not be presented as paid-relay acceptance.

Let each neighbor earn its share.

Use fresh accounts configured for paid service, a compatible test mint and small test balances. The Freedom UI sets initial terms and displays status; funding, purchasing and settlement currently use the operator/client workflow.

  1. Agree on a mint. Peers must accept the same compatible mint for their channel relationship. The mint is trusted to honor tokens and settlement.
  2. Fund the paying nodes. A relay needs working capital for its onward channel; incoming signed credit is not immediately spendable cash.
  3. Authorize the destination and budget. The sender accepts a bounded aggregate route quote. Each relay adds its fee to the onward cost and buys service from its next neighbor.
  4. Watch automatic updates. Persistent neighbor channels accumulate payments across many packets. Prices, quotas, channel capacity and lifetime caps bound what can be spent.
  5. Settle and verify recovery. Preserve account state through failures. A lost reply does not prove that a financial operation failed; use its retained recovery state.

Returning traffic needs separate spending authority unless an explicit free or return allowance applies. Delivery remains best effort. Route quality monitoring can guide selection; it is not a delivery receipt.

Check the basics first.

“Starting or unavailable” never changes

Check NTP synchronization, persistent state storage and the configured interface. Native interfaces need carrier, must be unbridged and must have lower-layer mesh forwarding disabled. Inspect service logs and the private status control; avoid reinitializing an existing account.

The service runs, but there are no peers

Check matching mesh ID, channel and radio security, actual peer association, stable MACs and discovery settings. For configured IP transports, verify addresses, reachability and admission configuration. Being on the same management LAN does not automatically establish the intended native mesh path.

The price fields are disabled

The account already exists, or your LuCI user has read-only access. Saved financial terms are intentionally fixed. Do not remove wallet or journal files to unlock the form.

A paid flow stops

Check the remaining payment budget, channel capacity, onward price limit, wallet balance and mint availability. Confirm both directions are authorized. Preserve pending operation state and follow the recovery instructions rather than repeatedly funding or resetting the account.

My phone joins Wi-Fi but has no internet

This setup provides FIPS connectivity. A compatible client is needed to use it, and an ordinary internet exit is a separate service. The isolated customer network intentionally does not grant unrestricted LAN or internet access just for joining.
